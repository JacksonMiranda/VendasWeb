# Contribuindo para o VendasWeb 🤝

*[English](#english) | [Português](#português)*

## Português 🇧🇷

Agradecemos seu interest em contribuir para o VendasWeb! Este documento fornece diretrizes para contribuições.

### **Como Contribuir**

1. **Fork** o repositório
2. **Clone** seu fork localmente
3. **Crie** uma branch para sua feature (`git checkout -b feature/amazing-feature`)
4. **Faça** suas alterações seguindo as diretrizes de código
5. **Teste** suas alterações
6. **Commit** suas alterações (`git commit -m 'feat: add amazing feature'`)
7. **Push** para a branch (`git push origin feature/amazing-feature`)
8. **Abra** um Pull Request

### **Padrões de Código**

- Siga as convenções de nomenclatura do C#
- Use EditorConfig para formatação consistente
- Mantenha métodos pequenos e focados
- Adicione comentários para lógica complexa
- Execute testes antes de submeter PR

### **Padrões de Commit**

Usamos [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` nova funcionalidade
- `fix:` correção de bug
- `docs:` documentação
- `style:` formatação
- `refactor:` refatoração
- `test:` testes
- `chore:` tarefas de manutenção

### **Processo de Review**

1. Todos os PRs devem passar pela review
2. Certifique-se de que os testes estão passando
3. Mantenha PRs pequenos e focados
4. Responda aos comentários de review

### **Reportando Issues**

- Use templates de issue disponíveis
- Forneça informações detalhadas
- Inclua passos para reproduzir bugs
- Adicione capturas de tela quando relevante

## English 🇺🇸

Thank you for your interest in contributing to VendasWeb! This document provides guidelines for contributions.

### **How to Contribute**

1. **Fork** the repository
2. **Clone** your fork locally
3. **Create** a branch for your feature (`git checkout -b feature/amazing-feature`)
4. **Make** your changes following code guidelines
5. **Test** your changes
6. **Commit** your changes (`git commit -m 'feat: add amazing feature'`)
7. **Push** to the branch (`git push origin feature/amazing-feature`)
8. **Open** a Pull Request

### **Code Standards**

- Follow C# naming conventions
- Use EditorConfig for consistent formatting
- Keep methods small and focused
- Add comments for complex logic
- Run tests before submitting PR

### **Commit Standards**

We use [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation
- `style:` formatting
- `refactor:` refactoring
- `test:` tests
- `chore:` maintenance tasks

### **Review Process**

1. All PRs must go through review
2. Ensure tests are passing
3. Keep PRs small and focused
4. Respond to review comments

### **Reporting Issues**

- Use available issue templates
- Provide detailed information
- Include steps to reproduce bugs
- Add screenshots when relevant
