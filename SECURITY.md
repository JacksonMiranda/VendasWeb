### **Reportando uma Vulnerabilidade**

Se você descobrir uma vulnerabilidade de segurança, por favor **NÃO** abra uma issue pública.

Em vez disso:

1. **Envie um email** para: jackson.miranda@example.com
2. **Inclua** uma descrição detalhada da vulnerabilidade
3. **Forneça** passos para reproduzir o problema
4. **Aguarde** nossa resposta (geralmente em 48 horas)

### **Processo de Divulgação**

1. Recebemos o relatório de vulnerabilidade
2. Confirmamos o recebimento em 48 horas
3. Avaliamos e validamos a vulnerabilidade
4. Desenvolvemos uma correção
5. Testamos a correção
6. Lançamos a correção
7. Divulgamos publicamente após a correção

### **Práticas de Segurança**

- Mantenha dependências atualizadas
- Use HTTPS em produção
- Não exponha informações sensíveis em logs
- Valide todas as entradas do usuário
- Use autenticação e autorização adequadas

## English 🇺🇸

### **Supported Versions**

We currently provide security updates for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |

### **Reporting a Vulnerability**

If you discover a security vulnerability, please **DO NOT** open a public issue.

Instead:

1. **Send an email** to: jackson.miranda@example.com
2. **Include** a detailed description of the vulnerability
3. **Provide** steps to reproduce the issue
4. **Wait** for our response (usually within 48 hours)

### **Disclosure Process**

1. We receive the vulnerability report
2. We confirm receipt within 48 hours
3. We assess and validate the vulnerability
4. We develop a fix
5. We test the fix
6. We release the fix
7. We publicly disclose after the fix

### **Security Practices**

- Keep dependencies updated
- Use HTTPS in production
- Don't expose sensitive information in logs
- Validate all user inputs
- Use proper authentication and authorization
